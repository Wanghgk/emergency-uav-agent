# 可配置机队协同搜救

Windows CMD 或 Anaconda Prompt，在仓库根目录执行。首次准备官方场景、模型权重、Conda 环境和网页见 [Windows 部署](deployment-windows.md)。

```cmd
conda activate emergency-uav-agent
python -m scripts.run_fleet --deepseek --task-id 290
```

`--deepseek` 使用 Windows 用户环境变量 `DeepseekApikey`。省略该参数使用本地规则，外部请求失败也会回退到可执行候选并记录原因。可把任务号换成 `28`（鳌太线）、`370` 或 `372`（K2）。诊断运行可加 `--points-per-scout 4`，每架感知机每轮只搜索四个点。默认上限两轮，每轮按完整网格生成路线。

默认 2 架感知机、1 架通导机。在启动新任务时用 `--scouts` 和 `--relays` 手动调整。支持 1–6 架感知机、0–4 架通导机。通导机为 0 架时改用基站直连。多架通导机各自负责分配到的感知机，可通过任意一架有完整链路的通导机转发观测。

机队任务默认使用 `configs/fleet_alarms.json` 中的粗略接警范围，边长为 220 米，飞行分区和检测过滤均采用这个范围。坐标是报警大致位置，可通过 `--alarms` 指定其他配置。默认模拟单段链路距离为 320 米，转场距离超出时需要中继。

网页「启动新任务」可以选择罗布泊、鳌太线、K2 雪山及其已配置任务，调整机队数量并开始飞行。勾选「快速试飞」时每架感知机飞一轮、最多六个航点。网页服务需从项目 Conda 环境启动，使用单个 Uvicorn 服务进程。同一时间只运行一个 AirSim 场景。缺失地图会在任务选项里标明，启动日志保存在 `data/launch-logs`。

任务列表和当前任务旁会显示任务状态。点击「删除任务」并确认后，任务、观测和关联产物会永久删除。由当前网页启动且仍在运行的任务会先停止仿真。

```cmd
python -m scripts.run_fleet --task-id 290 --scouts 3 --relays 2
```

完成网页构建后，在另一个 CMD 窗口运行下列命令，打开 [本地网页](http://127.0.0.1:8000)，选择“机队协同”。实时模式下，地图按每秒的位置采样更新各机标记。用地图的加减按钮调整缩放，放大后可拖动。“隐藏目标区路径”控制报警区内的搜索规划线。地图不绘制无人机历史拖尾和通信连线，通信链路状态可在地图下方展开。每架感知机都有独立图像窗口，并显示该机最近一帧的时间。播放或拖动时间轴时，各窗口更新到当前回放时间已采集的最近一帧。右侧协同日志可以独立滚动，最新事件在前。

```cmd
conda activate emergency-uav-agent
python -m uvicorn backend.api.main:app --host 127.0.0.1 --port 8000
```

## 规划、执行和反馈

- 感知机在各场景预先配置的救援入口附近以分隔位初始化，并走不同高度的首轮转场航线。搜索区按感知机数量分区。每架感知机独立推进轮次，后续轮次按照当前点到下一航点的地形高度接续搜索。单机搜索故障会记录在该机名下，其余飞机继续执行。
- 每轮由模型在经过边界约束的东西向、南北向往返航路中选一条。后续请求附带已执行方向、已收到帧数、人员候选数量及航路距离摘要。
- 通导机按点飞行，不采集搜救影像。调度器约每秒读取各机的共用地图 NED 位置，用视线地形遮挡和最大通信距离评估基站及感知机链路。航向改变、链路状态变化或预计要明显改点时，按最短调用间隔向模型请求候选决策。模型只接收当前可选点的代号、模拟余量、端到端连通状态和预计移动距离。调度器用最新位置复核返回值。急需移动时，本地调度立即执行可用候选。
- 感知机在飞行途中按固定周期采集，默认每 3 秒检查一次。可用 `--frame-interval 5` 改为每 5 秒。默认使用 RT-DETRv2 R18 提议候选、YOLO11s-Pose 裁剪复核。每帧复核置信度最高的三个候选，至少需要三个有空间分布的人体关键点，并且涉及躯干及另一身体部位。配准正常时用深度和相机位姿估计地图位置。RGB-D 校验不通过时仍回传图像和二维检测框，定位留空。
- 当感知机到通导、通导到基站均连通时才转发感知反馈，掉链时本机缓存。此链路为距离与地形视线仿真。三架飞机实际由同一 AirSim RPC 服务控制，网络传输性能、干扰和导航增强未建模。
- 达到报警人数且有多帧支持时，请模型决定是否结束。否则执行到搜索预算耗尽。多帧候选仍受识别与定位误差影响，任务结束和搜救人数分别记载。日志、观测分别保存在 `data/missions` 和 `data/observations`。飞行由脚本管理单个模拟器进程。

飞行阶段模型请求包括公开任务、航路摘要、观测统计和链路摘要。搜索结束后，可为多帧确认位置规划地面路线。该阶段的模型请求另包含人员估计位置、粗地形和请求的局部原分辨率切片。完整原始地形、影像和 ESARBench 隐藏答案留在本机。[地面路线和数据边界](ground-rescue.md)
