# 三地图接警搜救

| 场景 | 官方任务 | 报警人数 |
| --- | --- | --- |
| 罗布泊 | 290 | 5 |
| 鳌太线 | 28 | 1 |
| K2 雪山 | 372 | 2 |
| K2 雪山白天对照 | 370 | 2 |

任务启动时读取 [模拟报警配置](../configs/rescue_alarms.json)。实验准备时将官方任务中的人员分布量化为 50 米网格上的报警中心，使用 80 米见方的搜索区域。配置模拟调度员收到的粗略位置，正式飞行只使用这一区域和公开任务描述，精确目标坐标留给独立评估。

无人机从官方起点转场到报警区域，使用 UE5 俯视深度确定转场和搜索航段的地形净空。局部航线覆盖整个报警区域，后续一轮改用交叉方向降低漏扫概率，可回到单帧候选位置附近从另一视角复查。检测依赖实采前视 RGB，深度可靠时才保存人员估计位置。候选需在两个独立观测帧中重复出现才计入机上确认人数。

到达预计确认人数后结束搜索，碰撞、无效地形或搜索次数到限时记录原因。离线评估按 4 米水平阈值，将确认位置与官方人员一对一匹配，再报告复核找到和未找到的人数。网页显示报警范围、航迹、检测位置和复核数量。

## CMD 运行

先完成 [Windows 部署](deployment-windows.md)，再从仓库根目录运行。

```cmd
conda activate emergency-uav-agent
python -m scripts.run_rescue --task-id 290 --deepseek
python -m scripts.run_rescue --task-id 28 --deepseek
python -m scripts.run_rescue --task-id 372 --deepseek
python -m scripts.run_rescue --task-id 370 --deepseek
```

每条命令独占本机仿真端口 41451。UE5 退出后再启动下一条任务。沿用 `DeepseekApikey` 配置，省略 `--deepseek` 时使用固定入口策略做本地调试。

从另一个 CMD 窗口运行 `python -m uvicorn backend.api.main:app --host 127.0.0.1 --port 8000`，在页面选择“接警搜救”记录。每次运行的 JSON 报告位于 `data/missions`。

达到预计确认人数时，规划模型会根据确认数、候选数和剩余搜索机会建议结束或继续。搜索用完时也会生成结束评估，缺少的人员保留为未确认。任务下方的“搜救结果”按去重后的位置显示两套三维坐标和实采带框照片，可点击照片跳转到原始帧。旧报告可回看照片和位置，页面显示为历史任务。

## 实测与离线补检

以下历史报告来自原开发机器。重新运行后，用新任务输出的报告 ID 替换离线补检及复飞命令中的示例 ID。

罗布泊 #290 用 62 帧完成 1,431.7 米航迹，机上搜索核验 4/5 人。对同一批实采 RGB-D 做图像旋转补检后，新增倒地目标的多帧定位，独立复核 5/5。飞行日志仍保留在线结果。K2 夜间 #372 飞了 1,143.1 米，采集 62 帧，复核 0/2。

鳌太线 #28 经 62 帧网格搜索和 30 帧候选点复飞，自动复核为 0/1。两个低置信观测的水平估计相差约 0.13 米，画面有树枝遮挡，仍保留为未确认。飞行报告为 `2ae5ea63af6b4fcfb5a893736fbaa57a` 和 `ce43619f40a54357bedda0004a0471d3`。

K2 白天 #370 的 62 帧搜索获得 1 个单帧匹配候选。以该航拍候选为中心做四方向复飞后，独立复核确认 1/2 人。两名人员均在外置近景中可见，其中一人被雪坡部分遮挡。陡坡处机载诊断相机未通过预设位姿检查，渲染结论来自外置近景和 Actor 坐标。飞行报告为 `cb12d702c61a4f0dbe8b1d46c45a327e` 和 `3ef401adde364b9f9c31f1ea86e90818`。

```cmd
python -m scripts.recheck_rescue bd34d685247f40a588f89977561a0143
```

要从上次飞行实际定位的候选点采集四个方向的近景，可指定上一轮的报告 ID。复飞读取前一轮观测位置，使用新的画面做人员确认。

```cmd
python -m scripts.run_rescue --task-id 28 --revisit-run 2ae5ea63af6b4fcfb5a893736fbaa57a
```
