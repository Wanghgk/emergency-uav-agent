# 地面救援路线

三机搜索结束后，系统为每个多帧确认的人员估计位置规划一条从入口出发的接近路线。多帧确认来自感知观测。回放默认从首帧开始，到时间轴末尾的“任务结果”时才显示规划路线和人员结果。首次发送人员估计位置、观测点水平离散范围、入口、候选走廊的粗网格以及候选路线摘要。DeepSeek 通过结构化响应选择一至两个窗口，后端回发对应的原分辨率切片。切片包含西北像素中心坐标、南向和东向采样间距、表面高程及坡度。无效采样使用 `null`。原分辨率约 2.34 米，完整 DSM 按运行编号保存在本机。

候选由原分辨率栅格的八邻域搜索生成，分别优先短距离与缓坡。规划先用半径 12 米的地形邻域估算局部基面，标记比基面高 1.25 米以上的凸起、超过 35° 的陡变和缺测点，再加入约 3.5 米的栅格缓冲。粗网格和原分辨率切片都会发送障碍标记，粗格包含任一障碍子格就会打标。模型选择候选或返回需复核。后端逐格复核障碍、深度、表面坡度和相邻网格高差，以及终点距人员估计位置是否在 12 米内。路线坡度上限仍为 30°。这些阈值用于仿真筛查，无法确认树下地面、积雪、小障碍和最后一段的实际通行性。

## UE5 地形的三角网表示

运行中的地形来自当前 ESARBench 任务的 UE5 场景。AirSim 正射深度被转换为 NED 表面高程，并采用与 OBJ 兼容的规则连接三角网表示。每个相邻的四顶点单元沿西北到东南切成两个三角面，每个面内的高度用分片线性函数求得。模型请求携带实际顶点坐标轴、高程、三角连接规则和障碍掩码。缺测顶点不参加三角面插值。

首次请求的 `terrain_overview` 覆盖正射采集到的整片 1.2 × 1.2 公里工作地图，最多 17 × 17 个顶点，同时发送更密的候选走廊地形 `terrain_summary`。模型选定窗口后，再发送原分辨率三角网。抽稀网格仍保留覆盖块内是否存在障碍的标记。后端以完整采样网格复核路线，示例 OBJ 文件不参与线上任务。这个高程三角网源于 UE5 的实际渲染深度。

## 场景入口

入口在任务工作区外围，作为从场景外抵达的仿真入口。无人机起飞位置与地面起点共享同一区域，机组位置和高度分隔。表中坐标均为 AirSim NED 米。

| 场景 | 北 / 东 | 基准 Down | 入口依据 |
| --- | ---: | ---: | --- |
| 罗布泊 | 1380.0 / 1320.0 | 2.0 | 北侧远端开阔地，参考坡度约 4.3° |
| 鳌太线 | −25.0 / −10.0 | −3.125 | 东侧远端缓坡，参考坡度约 15.4° |
| K2 | 55.0 / −780.0 | 190.65 | 北侧远端雪坡，参考坡度约 17.7° |

临时生成的三架飞机先置于正射采集范围外，完成地形测量后再移到入口起飞位置。入口每次实测高度须与基准相差不超过 5 米，并通过局部坡度检查。持续向场景外通行及实际救援队的地面进入能力尚未验证。

## 在 Windows CMD 运行

```cmd
conda activate emergency-uav-agent
python -m scripts.run_fleet --deepseek --task-id 290
```

历史回放使用实际飞行观测与对应任务的 DSM。先运行 `python -m scripts.compare_terrain` 准备早期任务的本地地形。新版三机任务的实际采集网格保存在 `data/ground-terrain/<run_id>.npz`，回放会优先使用该文件。

```cmd
python -m scripts.plan_ground_rescue --run-id bd34d685247f40a588f89977561a0143 --deepseek
```

换成自己的运行编号即可。省略 `--deepseek` 可用本地规则。回放输出保存在 `data/ground-routes`，FastAPI 会将结果附到对应的任务上。网页入口见 [三机任务](fleet-mission.md)。

## 回放验证

罗布泊历史实采记录中有四个多帧人员估计位置。DeepSeek 实际请求了原分辨率窗口，为四个估计位置选择缓坡优先候选，长度为 276–332 米。路线经过原网格复核。K2 历史记录有一个多帧估计位置，在当前入口和坡度约束下无连通候选。鳌太线历史记录仅有单帧候选，未触发规划。这些结果用于验证仿真链路，人员身份和实际地面通行性仍需要复查。
