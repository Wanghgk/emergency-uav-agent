# 地面救援路线的地形表示选型

从 ESARBench 实际渲染的正射深度中，截取罗布泊任务 290、鳌太线任务 28 和 K2 任务 370 各一块约 450 × 450 米的区域，窗口居中于官方起点和报警区中心之间。原采样间距约 2.34 米。三地各留出 34,848 个像素检验重建，每种方法使用同一批检验点。高程为 NED 的负 Down。原始深度是可见表面，可能包含树冠、岩石和场景物体，属于数字表面模型（DSM）。[USGS 高程模型术语](https://www.usgs.gov/publications/digital-elevation-models-terminology-and-definitions)

## 表示方法

| 方法 | 模型收到的数据 | 适合用途 |
| --- | --- | --- |
| 整体二次曲面 | 六个系数和坐标范围 | 向模型概括区域地形走势，复杂坡折会被平滑 |
| 双线性高程网格 | 25 × 25 个高度，约 18.75 米间距 | 直接对齐地图坐标，容易查询任意点和剖面 |
| 固定三角网 (TIN) | 相同高度节点，每格固定对角线分成两片 | 模拟三角网分片，接近 3D GIS 表达。实验使用规则点集，未测量在山脊、沟谷加密的自适应 TIN |
| 分片双三次曲面 | 同一组 25 × 25 高度点，按邻点还原局部曲面 | 表面更连续，陡坡和边界附近需检查插值过冲 |
| 较密双线性网格 | 49 × 49 个高度，约 9.38 米间距 | 保留更多局部地形，数据量较大 |

等高线也可作为人机共享的地图图层。它让人容易辨认山脊和谷地，离散等高线之间的坡度及障碍需另由 DEM/DSM 或矢量要素查询，因此未纳入这次点高程重建排名。实际 GIS 三角瓦片可以多分辨率存储。[Cesium Quantized Mesh 规范](https://github.com/CesiumGS/quantized-mesh)

## 实测

每格为 **高程 RMSE（米） / 陡坡漏判率**。陡坡指原始 DSM 局部坡度大于 30°，漏判率的分母是该场景测试集中的陡坡像素。30° 仅作为实验分类阈值。大小是带坐标范围和高度编码的紧凑 JSON 的 UTF-8 字节数。

| 方法 | 罗布泊 | 鳌太线 | K2 | JSON 大小 |
| --- | ---: | ---: | ---: | ---: |
| 整体二次曲面 | 2.282 / 100.00% | 6.512 / 81.59% | 10.370 / 12.89% | 201–206 B |
| 双线性 25 × 25 | 1.057 / 84.80% | 2.516 / 41.41% | 0.374 / 1.86% | 2,965–4,579 B |
| 固定三角网 | 1.151 / 82.04% | 2.587 / 41.47% | 0.378 / 2.19% | 2,966–4,580 B |
| 分片双三次 | 1.082 / 71.69% | 2.684 / 38.38% | 0.316 / 1.82% | 2,964–4,578 B |
| 较密网格 49 × 49 | 0.694 / 30.67% | 2.279 / 30.77% | 0.167 / 1.30% | 10,866–17,061 B |

罗布泊验证集的陡坡采样有 763 个，较密网格仍漏掉约三成。鳌太线较密网格的平均坡度绝对误差仍有 8.08°，粗网格的高程 RMSE 改善也无法消除这一问题。K2 这块窗口的海拔变化可由较少采样点较好重建，实际通行性还取决于坡面、积雪和已知路径。

## 选型结果

已选择粗网格概括走廊、按需读取原分辨率切片的方案。已完成的接口、场景入口和复现方式见 [地面救援路线](ground-rescue.md)。本页的实验数据继续用于对比高程表示。

## 在 CMD 复现

```cmd
conda activate emergency-uav-agent
python -m scripts.compare_terrain --refresh
```

`data/terrain-comparison` 生成原始深度高程栅格（NPZ）、各方法的示例载荷（JSON）、完整指标（CSV）和绝对误差图（PNG）。图中每行一个场景，前两列是原始表面和坡度，其余列共用 0–5 米的绝对高程误差色阶。
