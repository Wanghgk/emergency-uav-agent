# ESARBench 地形如何发送给大模型

当前工程通过 AirSim 从正在运行的 UE5 场景采集正射深度，在本地建立数字表面模型（DSM）。地面救援阶段，后端先用全分辨率地形生成候选路线，再将粗粒度全图、候选走廊和按需选取的原分辨率窗口作为 JSON 发给大模型。模型负责复核并选择候选路线，后端负责计算航路和执行通行约束。

```text
UE5 当前场景 → AirSim 正射深度 → 本地全分辨率 DSM
                                      ↓
多帧确认的人员估计位置 + 救援入口 → 本地筛出候选路线
                                      ↓
请求 1：全图粗网格 + 走廊粗网格 + 路线摘要 → 模型选检查窗口
                                      ↓
请求 2：重复上述上下文 + 原分辨率窗口 → 模型选路线或要求复核
                                      ↓
后端逐格校验 → 任务记录与网页回放
```

## 1. 原始数据和坐标

- 俯视正射相机采集 **1,200 × 1,200 米**的任务工作区。深度栅格为 **512 × 512**，栅格间距约 **2.344 米**。范围由本次采集的相机和任务决定。
- 地图坐标统一为 AirSim NED 米，定位点为 `[北, 东, Down]`。相机垂直朝下时，表面 Down 等于相机 Down 加平面深度；发给模型的表面高程等于负 Down。这个高度以场景坐标原点为参考。
- 完整深度地形保存在本地 `data/ground-terrain/<run_id>.npz`。正射 RGB 底图供网页浏览；任务的原始 NPZ、RGB 图像、UE5 场景文件、示例 OBJ、官方人员和线索真值均不进入地面路线请求。
- DSM 描述相机可见的表面，可能包含树冠、岩石表面和积雪。现有数据无法直接确定树下地面、雪层稳定性和人员脚下的实际通行状况。

## 2. 地形在 JSON 里的表示

地形包使用规则三角网（TIN）。相邻四个样点按西北—东南对角线切成两个三角面 `NW–NE–SE` 和 `NW–SE–SW`。每个三角面内的高度是顶点的分片线性插值，可写成 `H(N, E) = aN + bE + c`。请求发送顶点坐标轴、高程矩阵和连接规则，接收方可据此重建三角面。这个表示可以转为 OBJ 的顶点和面；在线发送的是下列 JSON 字段。

| 字段 | 内容 |
| --- | --- |
| `vertex_north_m`、`vertex_east_m` | 每一行的北坐标、每一列的东坐标。北坐标从北往南递减，东坐标从西向东递增。抽样保留末行末列，末段间隔可能与名义间距不同，应按坐标轴数组还原。 |
| `surface_height_m` | 场景表面高程矩阵，值为负 Down。缺测为 `null`，含缺测顶点的三角面不用于插值。 |
| `surface_slope_deg` | 原分辨率地形上计算得到的局部坡度，随同高程采样发送，单位为度。 |
| `contains_blocked_cells` | 障碍或缺测标记。抽稀块只要覆盖一个不可通行单元就标记；平滑插值不能消除这一标记。 |
| `geometry`、`surface_function`、`cell_diagonal`、`triangle_rule` | 网格的拓扑和几何解释。系统无需为整片地形拟合一个全局函数。 |

## 3. 请求的时机和内容

无人机在飞行期间会调用模型选择搜索方向、通导位置和是否继续搜索，这些调用使用任务、候选航线和状态摘要。地面路线专用的地形包在搜索结束后发送，触发条件是**至少有一个多帧确认的人员位置，且该人员至少有一条通过本地筛查的接近路线**。每个符合条件的人员单独走以下流程。

| 请求 | 后端发送 | 模型返回 |
| --- | --- | --- |
| 第一次 | `terrain_overview` 覆盖整个已采集工作区，通常为 **17 × 17**。同时发送更密的候选走廊 `terrain_summary`、检查窗口的编号和位置、入口与人员估计坐标、水平观测离散范围，以及候选路线的长度、爬升、坡度和预览点。 | `{"window_ids":["approach","short_steepest"]}`，选择 1–2 个已有窗口。 |
| 第二次 | 重发第一次的上下文，增加所选窗口的 `terrain_details`。窗口围绕目标附近、候选路线最陡处或中点，最多 **9 × 9** 个原分辨率样点，间距约 **2.344 米**。 | `{"route_id":"gentler","rationale":"……"}`，选择已有路线。也可返回 `"route_id":null`，表示需要人工复核。 |

使用 DeepSeek 时，后端向 `/chat/completions` 发起 POST，地形包是 `messages` 中用户消息的 JSON 文本，系统消息约束返回格式。没有启用 DeepSeek 时，默认由本地规则完成同一选择流程，无外部请求。调用失败或返回无效选项时，后端从已通过筛查的候选中选择最大坡度较低、距离较短的路线。

用罗布泊运行 `e1304b` 的真实地形和一名确认人员离线复现组包，截获了请求体并使用模拟响应。第一次约 **14.9 KB**，含 17 × 17 全图和 23 × 12 走廊；第二次约 **19.9 KB**，额外含两个 9 × 9 窗口。这里统计的是 HTTP JSON 请求体字节数，未测实际 API 的 Token 或延时。

## 4. 大模型前后各做一次本地约束

- 请求前，后端按原分辨率栅格搜索最短和缓坡优先的候选。它以 12 米邻域估算局部基面，将高于基面 1.25 米以上的凸起、超过 35° 的陡变和缺测列为风险，并对风险格做约 3.5 米的缓冲。
- 路线必须通过原栅格的 **30° 坡度上限**、有效深度和障碍检查，终点距人员估计位置的水平距离需在 **12 米**以内。模型选定后，后端再次逐格复核，并校验相邻格之间的实际高差和斜穿障碍边界的情况。
- 鳌太线 #28 的运行 `8ceffd` 没有多帧确认目标，地面规划调用为 **0 次**。K2 #372 的运行 `bd72d6` 有一名确认目标，但其 12 米内的地形格坡度最低约 **32.7°**；按当前约束从指定入口可达的最近格仍距目标约 **89 米**。本地没有候选路线，地面规划调用同样为 **0 次**。

## 5. 可带到新对话的问题

1. 如何在维持岩石和陡坡约束的同时，把当前 DSM 改成更适合步行规划的地面模型？需要区分裸地高程、树冠遮挡和实际障碍。
2. 陡峭地形下，本地拒绝接近路线时，是否应单独生成可达的集结点，或允许模型提出走廊供后端逐格验证？如何表示可达区和未覆盖区？
3. 固定粗网格可能丢失窄路、沟谷和坡折。应如何比较按需原分辨率窗口、坡折处分区加密和不同分辨率瓦片的效果与请求大小？
